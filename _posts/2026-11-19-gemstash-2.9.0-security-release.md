Today the RubyGems team released Gemstash 2.9.0, which fixes 8 security vulnerabilities affecting earlier versions. The most serious one is an unauthenticated remote code execution bug, rated Critical with a CVSS v4.0 score of 10.0. If you run Gemstash anywhere, please upgrade to 2.9.0 right away, or turn the service off until you can.

## What is Gemstash and how does it relate to the RubyGems CLI and RubyGems.org?

Gemstash is a small Ruby server that sits between RubyGems and Bundler clients and an upstream gem source, which is RubyGems.org by default. It caches gems so installs are faster and keep working when the upstream can't be reached, and it can host private gems too. Older versions let clients pick which upstream Gemstash fetches from, and that's where several of these vulnerabilities start. [RubyGems.org](https://rubygems.org) and the RubyGems CLI are not affected by any of the vulnerabilities we're disclosing today.

## The advisories

- Critical: Remote code execution through unsafe loading of upstream data ([GHSA-27cp-f4p8-8qwv](https://github.com/rubygems/gemstash/security/advisories/GHSA-27cp-f4p8-8qwv))
- High: Server-side request forgery and open redirect through client-chosen upstreams ([GHSA-xfw4-3v4j-82mr](https://github.com/rubygems/gemstash/security/advisories/GHSA-xfw4-3v4j-82mr))
- High: Memory exhaustion from oversized upstream responses ([GHSA-c927-fwqw-cm2g](https://github.com/rubygems/gemstash/security/advisories/GHSA-c927-fwqw-cm2g))
- Medium: Stored cross-site scripting through upstream content served from Gemstash ([GHSA-v438-gm7r-2pgf](https://github.com/rubygems/gemstash/security/advisories/GHSA-v438-gm7r-2pgf))
- Medium: Unvalidated dependency data cached from upstreams ([GHSA-xg28-cqw2-pggq](https://github.com/rubygems/gemstash/security/advisories/GHSA-xg28-cqw2-pggq))
- Medium: Pushes could overwrite yanked private gems ([GHSA-m64f-hhmc-w7qr](https://github.com/rubygems/gemstash/security/advisories/GHSA-m64f-hhmc-w7qr))
- Medium: The private dependencies API ignored protected fetch ([GHSA-7frx-567x-v3r6](https://github.com/rubygems/gemstash/security/advisories/GHSA-7frx-567x-v3r6))
- Medium: Unauthenticated memory use when receiving gem pushes ([GHSA-wgrc-4g2v-9qxv](https://github.com/rubygems/gemstash/security/advisories/GHSA-wgrc-4g2v-9qxv))

All advisories are listed at <https://github.com/rubygems/gemstash/security/advisories>.

## Before you upgrade

2.9.0 makes some changes to close these issues:

- It requires Ruby 3.3 or newer.
- Clients can no longer choose arbitrary upstream sources. Gemstash only fetches from upstreams on its allowed list, which is RubyGems.org by default. If your clients use other upstreams, add them to `:allowed_upstreams` before upgrading. See the [configuration docs](https://github.com/rubygems/gemstash/blob/main/docs/gemstash-configuration.5.md#allowed-upstreams).
- If an upstream redirects downloads to another host, such as a CDN, add that host to `:allowed_redirects`.
- Upstreams that only serve the old Marshal dependency format are no longer supported.
- Responses from upstreams now have size and time limits: 64 MiB per response (`:max_upstream_bytes`), and 300 seconds per request (`:max_upstream_duration`), with a minimum transfer rate after `:fetch_timeout`. Raise them if you fetch very large gems or have a slow link to your upstream.
- `gemstash start` now checks these settings and refuses to start if `:allowed_upstreams`, `:allowed_redirects`, or the new upstream limits are invalid.
- Cached dependency data is fetched again after the upgrade.

## Sunsetting Gemstash

Most of these reports are in how Gemstash fetches and caches gems from an upstream server, which is its core job, and keeping that safe takes ongoing security work. These days, many teams that need a private gem server or a RubyGems.org cache use a general-purpose artifact registry or package proxy instead, one that handles gems alongside all their other packages.

For these reasons, the RubyGems team has decided to sunset Gemstash. 2.9.0 is the last feature release. The RubyGems team will continue to work on reported vulnerabilities and bug fix contributions. We recommend that anyone running Gemstash plan a move to one of these alternatives:

- [JFrog Artifactory](https://docs.jfrog.com/artifactory/docs/rubygems-repositories): hosts private gems and proxies and caches RubyGems.org, self-hosted or as a service.
- [Sonatype Nexus Repository](https://help.sonatype.com/en/rubygems-repositories.html): hosted, proxy, and group gem repositories, which combine private gems and a RubyGems.org cache behind one URL.
- [Cloudsmith](https://docs.cloudsmith.com/formats/ruby-repository): a managed private gem registry that can proxy and cache RubyGems.org.
- [AWS CodeArtifact](https://docs.aws.amazon.com/codeartifact/latest/ug/configure-use-rubygems-bundler.html): managed gem repositories with an [external connection to RubyGems.org](https://docs.aws.amazon.com/codeartifact/latest/ug/external-connection.html).
- [GitHub Packages](https://docs.github.com/packages/working-with-a-github-packages-registry/working-with-the-rubygems-registry): hosts private gems next to your GitHub repositories, but does not proxy RubyGems.org.
- [An S3 bucket or S3-compatible endpoint](https://guides.rubygems.org/using-s3-source/): serves private gems without running a server, but does not proxy RubyGems.org.
